# Сервер историй Nur

Небольшой сервер без внешних пакетов. Он одновременно отдаёт PWA из родительской папки и принимает истории пользователей для ручной модерации. Каталог `backend/` и сохранённые заявки никогда не доступны как статические файлы.

## Запуск

Требуется Node.js 18.17 или новее.

1. Скопируйте `.env.example` в `.env` и задайте длинный непредсказуемый `ADMIN_TOKEN`.
2. Откройте терминал в папке `backend`.
3. Запустите `npm start`.
4. Откройте `http://localhost:8080`.

Для ручной очереди модерации откройте `http://localhost:8080/moderator.html` и введите тот же `ADMIN_TOKEN`. Токен не сохраняется на странице и не передаётся основному пользовательскому интерфейсу.

Зависимости устанавливать не нужно. В режиме разработки можно использовать `npm run dev`.

> Не размещайте `.env` в публичной папке и не передавайте `ADMIN_TOKEN` клиентскому приложению. Для внешнего доступа запустите сервер за HTTPS reverse proxy и ограничьте доступ к административному интерфейсу.

## Публичный API

### `GET /api/stories`

Возвращает только опубликованные истории, сначала новые. Поддерживаются параметры `limit` (1–100, по умолчанию 24) и `offset`.

### `POST /api/stories`

Принимает JSON и сохраняет историю со статусом `pending`. Допускаются только следующие поля:

```json
{
  "author": "Амина",
  "title": "Мой путь к исламу",
  "body": "Текст истории не короче 20 символов."
}
```

Ограничения: автор — 2–70 символов, заголовок — 3–120, текст — 20–3000. Размер всего JSON ограничен переменной `MAX_BODY_BYTES` (по умолчанию 16 KiB). Неподходящие или лишние поля отклоняются с понятным JSON-ответом.

Клиент должен показывать пользовательский текст только через `textContent`, а не через `innerHTML`.

## Административный API

Все запросы требуют заголовок `X-Admin-Token`. Если `ADMIN_TOKEN` не настроен, административные маршруты намеренно отвечают `503`.

### `GET /api/admin/stories?status=pending`

Список заявок. Значения `status`: `pending` (по умолчанию), `published`, `rejected`, `all`; также доступны `limit` и `offset`.

### `PATCH /api/admin/stories/:id`

Публикация, отклонение или правка заявки. `status` обязателен; другие поля необязательны и проходят ту же проверку, что и новая история.

```json
{
  "status": "published",
  "title": "Уточнённый заголовок"
}
```

Пример с `curl`:

```bash
curl -X PATCH "http://localhost:8080/api/admin/stories/ID" \
  -H "Content-Type: application/json" \
  -H "X-Admin-Token: ваш-длинный-токен" \
  --data '{"status":"published"}'
```

## Хранение и безопасность

Данные находятся в `data/stories.json`, создаются при первом запуске и исключены из Git. Каждая запись выполняется во временный файл, синхронизируется и затем атомарно переименовывается; операции записи выстраиваются в очередь. Это защищает от частичных файлов и потерянных одновременных заявок в рамках одного процесса Node.js.

По умолчанию CORS принимает только same-origin запросы. Для отдельно развёрнутого фронтенда перечислите точные origin через `ALLOWED_ORIGINS`, например `https://app.example.com,https://www.example.com`. Не используйте `*` вместе с административным API.
